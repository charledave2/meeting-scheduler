# Meeting Scheduler audit — 2026-11-10

Scope: Android app and authentication/authorization entry points in the Cloudflare API, based on v0.38.1. Changes ship in v0.39.0.

## Findings addressed

- Material3 surface-container roles were unset, allowing stock purple/lilac surfaces in dialogs and inputs. Both palettes now define all surface-container roles and surface tint explicitly.
- Profile/account bitmap decoding ran during composition. Avatar decoding now runs on Dispatchers.IO, samples images to thumbnail size and uses an 8 MiB shared bitmap cache keyed by a digest.
- The drawer's fixed header/footer could consume the available landscape height. The whole drawer now scrolls; login respects safe drawing and keyboard insets. The account dialog and participant popup have viewport-relative height limits. Update notes scroll separately from dialog actions.
- Schedule WebViews now block network loads, file/content access and user navigation. The export preview releases its WebView when removed. The existing escaped schedule HTML, layout dimensions and PNG compression remain unchanged.
- The FileProvider previously exposed the entire cache directory. Only the exports subdirectory is now shareable. App backup is explicitly disabled to protect local schedules and session material.
- API redirects are disabled on authenticated Android requests. Signing out clears the local token immediately and attempts server-side revocation of that specific session without touching a later login.
- APK update downloads now accept only the configured repository's release APK URLs and use a fresh download filename for retries. Android continues to verify package signatures during installation.
- Administrator bootstrap previously accepted an unsigned identity header. Bootstrap now requires cryptographic Cloudflare Access JWT verification.
- Mandatory password changes were enforced mainly through UI. Authenticated API calls now reject those accounts until the password is changed; identity lookup and password-change endpoints remain available.
- API responses now send no-store and nosniff headers. Existing active-account checks, password hashing, login lockouts and mutation origin checks were reviewed.
- Android 7 was declared supported while java.time was used without core library desugaring. The build now backports the supported date APIs. Android lint is now part of the APK workflow.

## Palette decisions

Official schedule section colors (teal, ochre, red) and error/disable warning colors retain their semantic meaning. App chrome, dialogs, fields and navigation use the forest-green palettes in both themes.

## Validation and limits

XML resources were parsed locally. GitHub Actions runs debug/release compilation and Android lint; the Cloudflare workflow builds and deploys the backend. See the release workflow results for the outcome of those checks.

This is a source audit and build validation, not a penetration-test certification or a measured frame-rate benchmark. No phone/tablet emulator or signed-in device was available in this workspace. Physical-device checks remain necessary at 320 dp, 360 dp, tablet widths, landscape, split-screen and enlarged system fonts. Database/network latency and device GPU/memory behavior were not benchmarked. No claim of universal screen/device compatibility or absolute security is made.
